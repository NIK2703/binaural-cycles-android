# Аудит энергопотребления UI — Binaural Cycles

**Дата:** 2026-09-06
**Охват:** слой jetpack-compose (экраны, графики, панель, навигация) + фоновый
`BinauralPlaybackService`. Нативный движок C++ вне scope (см. §6).

**Главный вывод:** UI перерисовывается и перекомпоновывается примерно раз в
секунду ради значений, которые либо не читает, либо может не менять. Ключевой
механизм — два графических компонента объявляют параметры частот, которые
никогда не читают, а вызывающие коды кормят их «живыми» значениями (~1 Гц), из-за
чего инвалидируется кэш отрисовки и каждую секунду целиком перерисовываются
сетка, ~14 подписей осей и 5 путей по ~800–1000 сегментов.

---

## §0. Три канала, по которым UI тратит батарею

1. **CPU + GPU на перекомпозицию и перерисовку.** Каждый тик телеметрии
   перекомпоновывает дерево Compose; перекомпозиция пересоздаёт лямбды
   `drawBehind`, что инвалидирует узлы отрисовки и заставляет тяжёлые слои
   рисоваться заново.
2. **Пробуждения (wakeups).** `delay(1000)` в UI-джобе сервиса и `combine`
   телеметрии будят CPU раз в секунду. Чем реже меняются значения — тем реже
   будят.
3. **Binder-транзакции.** `NotificationManager.notify()` и
   `MediaSession.setMetadata()` — это IPC в `system_server`. Каждая такая
   транзакция стоит батареи; их число должно быть сведено к минимуму и
   продублировано только при реальной смене контента.

## §1. Схема потоков данных (до правок)

```
 engine (C++)                       service (BinauralPlaybackService)
 ┌──────────────┐                   ┌──────────────────────────────┐
 │ getFrequencies│──updateCurrent──►│ _currentBeatFrequency        │
 │ AtCurrentTime│   Frequencies()   │ _currentCarrierFrequency     │
 │  (сырые float)│                  │ _currentTimeOfDaySeconds      │
 └──────────────┘                   └──────────────┬───────────────┘
                                                    │
                                          combine 5 потоков
                                                    │
                                            observePlaybackState()
                                                    │  distinctUntilChanged()
                                                    ▼
                                          PlaybackTelemetry (StateFlow)
                                                    │
        ┌───────────────────────────────────────────┼───────────────────────────┐
        ▼                                            ▼                           ▼
 Navigation.kt (root)                       PresetListScreen              PresetEditScreen
   telemetry.collectAsState()                  telemetry                     telemetry
        │                                      │                            │
   BottomPlaybackPanel                PresetCard → MiniFrequencyGraph  FrequencyGraph
                                        (params: carrier/beat — МЁРТВЫЕ)
```

Красная нить: `telemetry` собирался в **корне** навигации → перекомпоновывал
весь `Scaffold`+`NavHost`; а графики получали частоты, которые **не читали** →
каждый тик перерисовывал статику.

## §2. Находки по приоритету

### P0 — блокирующие (самый большой выигрыш)

- **P0-1. Мёртвые параметры `currentCarrierFrequency` / `currentBeatFrequency`
  в `FrequencyGraph` + перерисовка статики на каждый тик.**
  Объявлены в сигнатуре (`FrequencyGraph.kt`), ни разу не читаются в файле.
  `PresetEditScreen.kt` передавал в них «живые» значения телеметрии. Результат:
  на каждый тик менялся параметр компонуемого → статический слой (сетка, 9
  часовых + 5 частотных подписей, 5 путей) перерисовывался заново.
  *Правка:* параметры убраны; статический `drawBehind` вынесен в
  `remember`-модификатор, который переиспользуется между перекомпозициями и
  не инвалидирует отрисовку. (см. §7)

- **P0-2. Мёртвые параметры в `MiniFrequencyGraph` + per-second вычисление
  в `PresetListScreen`.** `MiniFrequencyGraph` объявлял те же два параметра и
  не читал их; `PresetListScreen` для каждой активной карточки каждую секунду
  считал `getChannelFrequenciesAt()` и передавал carrier/beat.
  *Правка:* параметры убраны из сигнатуры, обоих вызовов и из `PresetCard`;
  per-second вычисление удалено (карточке частоты не нужны).

- **P0-3. Частоты в телеметрии НЕ квантованы.** Время уже квантовалось до 60 с,
  а частоты шли сырыми (~1 Гц) → `distinctUntilChanged` никогда не схлопывал
  эмиссии. *Правка:* beat квантуется до 0.1 Гц, carrier до 1 Гц (ровно в
  точность отображения `BottomPlaybackPanel`: `%.1f`/`%.0f`), эмиссии
  падают с ~1/с до ~1/мин.

### P1 — средние

- **P1-1. `telemetry` собирался в корне навигации.** Единственный потребитель —
  нижняя панель. *Правка:* подписка перенесена в `TelemetryDrivenPlaybackPanel`
  рядом с панелью; корневой `Scaffold` перестал перекомпоновываться на тик.

- **P1-2. 11 сайтов `collectAsState()` вместо `collectAsStateWithLifecycle()`.**
  **ИСКЛЮЧЕНО** по требованию «функционально ничего не меняется»: ниже
  `STARTED` значения перестали бы обновляться, что рискует показать устаревшее
  состояние при возврате на экран. (см. §8)

- **P1-3. Дублирование работы 30-с и 1-с джобов сервиса.** UI-джоб при экран
  включён + воспроизведение делает то же, что 30-с джоб, но чаще. *Правка:*
  30-с джоб пропускает итерацию, если жив UI-джоб (условия и порядок
  идентичны, публикация всё равно дедуплицируется по контенту).

- **P1-4. 1-Гц джоб сервиса тикает даже на паузе.** **ИСКЛЮЧЕНО**: именно этот
  тик держит актуальным указатель времени суток на экране; изменение интервала
  изменило бы видимый каденс указателя. (см. §8)

### P2 — низкие

- **P2-1. `BoxWithConstraints` в `FrequencyGraph`.** **ИСКЛЮЧЕНО**: замена на
  `Box`+`onSizeChanged` меняет момент получения размеров (после раскладки) и
  несёт риск мерцания при первой отрисовке/повороте. (см. §8)

- **P2-2. `points.indexOf(point)` в цикле — O(n²).** *Правка:* карта
  `точка → индекс` строится один раз через `remember(points)`, поиск стал O(1).
  Обход в обратном порядке сохраняет семантику «наименьший индекс» как у
  `indexOf`.

- **P2-3. Мёртвый `_elapsedSeconds` в сервисе.** Писался каждую секунду, не
  читался никем (grep по проекту — только запись). *Правка:* убраны поток,
  коллектор и сброс. `BinauralStreamManager.elapsedSeconds` не тронут.

- **P2-4. Два дублирующих `pointerInput { awaitPointerEventScope{while(true)} }`.**
  **ИСКЛЮЧЕНО**: инлайновые циклы ожидания событий при бездействии спят; выигрыш
  пренебрежимо мал, а удаление одного из двух несёт риск тонкого изменения
  жеста «закрыть всплывающее окно точки» на графике. (см. §8)

- **P2-5. OLED true-black фон.** **ИСКЛЮЧЕНО**: это явное визуальное изменение,
  прямо запрещённое требованием. (см. §8)

## §3. Что уже сделано хорошо (не трогать)

- Время суток уже квантовано до 60 с (U1).
- `BinauralUiState` и `PlaybackTelemetry` разнесены в разные потоки.
- Уведомление и метаданные медиасессии дедуплицируются по контенту
  (`lastNotifiedContent` / `lastMetadataContent`).
- Экран выключения кэшируется (`isScreenOn`) вместо binder-IPC `isInteractive`
  (U2).
- `MiniGraphCache` / `GridCache` кэшируют геометрию; `CardinalTension.forPoints()`
  считается один раз.
- `staticPaths`/`beatWeights` уже в `remember`.

## §5. Как проверять

- **Layout Inspector** (Android Studio): включить «Show Recomposition Counts»,
  проиграть пресет, подёргать скраб. Ожидаем: счётчик перекомпозиций
  `BottomPlaybackPanel` растёт ~1/мин (а не 1/с); `FrequencyGraph` перерисовывает
  статику только при правке кривой/смене темы.
- **gfxinfo:** `adb shell dumpsys gfxinfo com.binauralcycles` — меньше
  `Draw`/`Prepare` за тот же интервал.
- **batterystats:** `adb shell dumpsys batterystats --charged` до/после прогона.
- **Регрессия визуала:** скраб (красная/серая линии, кнопка сброса), панель
  частот (beat/carrier), список пресетов (активная карточка рисует указатель).
  Всё должно выглядеть тождественно.

## §6. Вне scope

Нативный движок C++ (`BinauralEngine`), WakeLock-логика `BinauralStreamManager`,
пакетный budget памяти, режим энергосбережения — отдельные темы, не затронуты.

## §7. Применённые правки (факт)

| ID | Файл | Что сделано |
|----|------|-------------|
| P0-2 | `ui/components/MiniFrequencyGraph.kt` | Убраны `currentCarrierFrequency`/`currentBeatFrequency` из сигнатуры, обоих вызовов `drawCachedGeometry` и из приватной функции. |
| P0-2 | `ui/screens/PresetListScreen.kt` | Убраны per-second `getChannelFrequenciesAt()` и два параметра из `PresetCard` (вызов + сигнатура + проброс в `MiniFrequencyGraph`). |
| P0-1 | `ui/components/FrequencyGraph.kt` | Убраны два мёртвых параметра из сигнатуры; статический `drawBehind` вынесен в `remember`-модификатор (ключи — все входы), чтобы не инвалидировать отрисовку на тик. |
| P0-1 | `ui/screens/PresetEditScreen.kt` | Убраны две строки передачи частот в `FrequencyGraph`. |
| P0-3 | `viewmodel/BinauralViewModel.kt` | В `observePlaybackState()` beat квантуется `round(beat*10)/10`, carrier `round(carrier)` (точность `%.1f`/`%.0f`). |
| P1-1 | `ui/navigation/Navigation.kt` | Удалена корневая подписка `telemetry`; добавлен `TelemetryDrivenPlaybackPanel`, держащий подписку у панели. |
| P1-3 | `service/BinauralPlaybackService.kt` | 30-с джоб пропускает итерацию, если активен 1-с UI-джоб. |
| P2-2 | `ui/components/FrequencyGraph.kt` | `points.indexOf(point)` заменён на `remember(points)`-карту `точка→индекс` (O(1)). |
| P2-3 | `service/BinauralPlaybackService.kt` | Удалены `_elapsedSeconds`, коллектор `audioEngine.elapsedSeconds`, сброс. `BinauralStreamManager.elapsedSeconds` сохранён. |

**Компиляция:** `:app:compileDebugKotlin` — проходит успешно (проверено после
правок).

**Почему это безопасно под «функционально и визуально ничего не меняется»:**
- Убранные параметры графиками не читались → картинка тождественна.
- Квантование выбрано ровно по форматам единственного потребителя → отображаемая
  строка не меняется ни на символ.
- Перенос подписки не меняет, ЧТО и КАК показывает панель, только то, какой
  узел перекомпоновывается.
- Статический кэш рисует те же примитивы теми же цветами и координатами.

## §8. Исключённые пункты (по требованию «функционально/визуально без изменений»)

1. **P1-2** — `collectAsStateWithLifecycle` (11 сайтов). Риск: ниже `STARTED`
   значения перестают обновляться → устаревший UI при возврате на экран.
2. **P1-4** — адаптивный интервал UI-джоба. Риск: изменение каденса указателя
   времени на экране (видимое поведение).
3. **P2-5** — true-black OLED-фон. Это прямое визуальное изменение.
4. **P2-1** — замена `BoxWithConstraints`. Риск мерцания при первой отрисовке
   и повороте (момент получения размеров).
5. **P2-4** — удаление дублирующего `pointerInput`. Выигрыш пренебрежимо мал,
   риск тонкого изменения жеста закрытия всплывающего окна точки.

Все пять сохранены как потенциальные следующие шаги, если пользователь снимет
ограничение на отсутствие изменений.
