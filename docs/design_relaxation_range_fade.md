# Угасание периодов расслабления по положению в диапазоне (`fadeByRangePosition`)

**Статус:** реализовано (модель, сериализация, кэш мини-графиков, UI, тесты —
`:core:audio:testDebugUnitTest` зелёный, 76+ тестов). Не делалось только §8.4
(`beatGatePercent` — фича из соседнего документа ещё не писана).

**Уточнение (option B, применено):** обе оси нормированы на **реальный размах
базовой кривой** (`[carrierLo; carrierHi]` / `[beatLo; beatTop]`), а не на
объявленный `carrierRange` и не от нуля для биений. Вес 0 в реальном минимуме,
1 в реальном максимуме. Переключатель в UI перенесён **над** слайдерами глубины;
производные числа («на пике / в минимуме») **не показываются** (удалены как
неверные). Детали — §2.1, §2.3, §6.1, §6.5, §8.1, §8.5.
**Цель:** опция в настройках предустановки, после включения которой глубина
снижения частот в периоде расслабления перестаёт быть константой: она тем
больше, чем ближе частота к ВЕРХНЕЙ границе своего диапазона, и стремится к
нулю у нижней. Несущая и частота биений оцениваются **независимо**, каждый со
своей опорной шкалой.

Связанный документ: `design_relaxation_beat_gate.md` (ограничитель территории
по `|beat|`) — код тоже не писан, но обе фичи делят один вспомогательный
примитив (§6.2) и ортогональны по смыслу: **gate отвечает «где», fade — «насколько
глубоко»**.

---

## 1. Что именно меняется

Сегодня глубина — две константы на весь пресет:

```
rawCarrier = carrier · (1 − carrierReductionPercent/100)
rawBeat    = beat    · (1 − beatReductionPercent/100)
```

С включённым угасанием константы превращаются в поле вдоль суток:

```
R_carrier(t) = carrierReductionPercent/100 · w_carrier(t)
R_beat(t)    = beatReductionPercent/100    · w_beat(t)       // независимо!
```

Слайдеры при этом меняют смысл: теперь они задают **глубину у верхней границы
диапазона**, а не глубину вообще. Это надо сказать в UI (§6.5), иначе
пользователь будет тщетно искать, куда делась его «−25 %».

Геометрия периода (времена `t1…t4`, длительность, переходы, пауза) **не
трогается вообще** — меняется только глубина. Инвариант «все интервалы ровно
из предустановки» из `design_relaxation_beat_gate.md` (§4.1) сохраняется
буквально.

## 2. Две оси и две разные опоры

### 2.1 Несущая: положение относительно реального размаха базовой кривой

```
carrierLo, carrierHi = реальный min/max carrier_base по сэмплам кривой
                       (CurveSampling.carrierMagnitudeExtremes)

u_carrier(t) = (carrier_base(t) − carrierLo) / (carrierHi − carrierLo)

w_carrier(t) = clamp(u_carrier(t), 0, 1)
```

Опора — **реальный размах самой кривой** (`carrierMagnitudeExtremes`), а не
объявленный `carrierRange`.

Почему отказались от объявленного диапазона (см. историю в §8.1): у
`carrierRange` есть запас снизу — реальный минимум кривой лежит **выше**
`carrierRange.min`. Нормировка на объявленный диапазон давала ненулевое
снижение (−4 % / −6 %) ровно в реальном минимуме, где по замыслу должен быть 0.
Пользователь увидел это как ошибку. Решение (option B, выбрано в ходе
реализации): нормировать **обе** оси на реальный размах кривой, чтобы вес
обращался в 0 ровно в реальном минимуме несущей и биений, и достигал 1 в
реальном максимуме.

Цена по сравнению с объявленным диапазоном:

1. **Появляется сэмплирование** кривой (как и для биений) — 720 точек,
   доли миллисекунды, только при смене настроек (R8).
2. **Правка точек кривой пере масштабирует шкалу веса** — ровно как и для
   биений: добавили точку на новом экстремуме → весь профиль угасания
   пересчитался. Приемлемо, потому что так пользователь видит на графике
   честную картину «впадина распрямляется у реального дна».
3. **Вырожденный размах → `w = 1`** (R4), а не «выключить»: плоская кривая
   не убивает режим расслабления молча.

### 2.2 Биения: почему хранимый `beatRange` не годится

Первое желание — взять `FrequencyCurve.beatRange` по аналогии с несущей. Оно
опровергается одним числом.

| Кандидат в «верхний предел биений» | Значение | Вес для `\|beat\| = 25 Гц` | Вердикт |
|---|---|---|---|
| `beatRange.max` (хранимый) | **1000 Гц** (`FrequencyMath.MAX_BEAT_MAGNITUDE`) | 0.025 | ✗ режим практически выключен |
| `maxFittableBeatMagnitude(carrierRange)` | ширина диапазона = 500 Гц | 0.05 | ✗ то же |
| `maxBeatMagnitude(carrier)` (геометрия) | 2·(440−20) = 840 Гц | 0.03 | ✗ это физический предел, а не дизайн |
| `max_t \|beat_base(t)\|` | 25 Гц (для «Циркадного ритма») | 1.0 | ✓ |

Причина: `beatRange` **не является пределом частоты биений ни по одному из
смыслов**. Это масштаб отрисовки маркеров, застывший на ±1000 Гц; предел модуля
всегда выводится из геометрии (см. KDoc `FrequencyCurve.effectiveBeatRange` и
`FrequencyMath.UNBOUNDED_BEAT_RANGE`). Реально используемые пресетами биения —
единицы и десятки герц. Нормировать их на 1000 Гц — значит обнулить фичу.

Отсюда вывод: **шкалы биений, «определённой для предустановки», в модели не
существует — её надо вычислить из самой кривой.**

### 2.3 Биения: опорная шкала `[beatLo; beatTop]` (реальный размах модуля)

```
beatLo, beatTop = реальный min/max |beat_base(t)| по сэмплам БАЗОВОЙ кривой
                  (CurveSampling.beatMagnitudeExtremes)

u_beat(t)    = (|beat_base(t)| − beatLo) / (beatTop − beatLo)
w_beat(t)    = clamp(u_beat(t), 0, 1)
```

Дно шкалы — **реальный минимум модуля биений кривой `beatLo`**, а не 0 Гц.
Причины (решение option B, синхронно с несущей §2.1):

1. **Совпадение с замыслом «0 на дне».** При нормировке на `[0; beatTop]`
   реальный минимум (3 Гц для «Циркадного ритма») получал вес `3/25 = 0.12` и
   ненулевое снижение −6 % — ровно то, что пользователь посчитал ошибкой.
   Смещение дна на `beatLo` даёт `w = 0` в реальном минимуме и `w = 1` в
   реальном максимуме, симметрично несущей.
2. **Физический смысл сохранён.** `|beat| = beatLo` — самый спокойный момент
   этого пресета; именно там период расслабления должен выродиться в базовую
   кривую (R6). Знак по-прежнему не важен (мера — модуль).
3. **Вырожденный размах закрыт R4.** Плоская кривая даёт
   `beatTop − beatLo <= FADE_SPAN_EPS` → `w_beat ≡ 1` (угасание инертно, как
   сегодня), без отдельного special-case. Симметрично несущей.
4. **Устойчивость сверху.** Правка любого участка кривой пере масштабирует
   шкалу, но это видно на графике и совпадает с поведением несущей.

Мера — **модуль** `|beat|`, а не знаковая величина: знак задаёт раскладку
каналов, а уровень возбуждения определяется скоростью пульсации (правило R2 из
`design_relaxation_beat_gate.md` переносится без изменений). Для всех штатных
пресетов `beat > 0` и разница не видна; для пресетов с отрицательными биениями
знаковая формула дала бы бессмыслицу («расслабляться только там, где правый
канал выше левого»).

### 2.4 Итог

```
carrier:  w_c = clamp((carrier_base − carrierLo) / (carrierHi − carrierLo), 0, 1)   // carrierLo/Hi — реальный размах несущей
beat:     w_b = clamp((|beat_base| − beatLo) / (beatTop − beatLo),           0, 1)   // beatLo/Top — реальный размах модуля биений
```

`carrierLo/carrierHi` и `beatLo/beatTop` берутся сэмплированием базовой кривой
(`CurveSampling.carrierMagnitudeExtremes` / `beatMagnitudeExtremes`). Обе оси
нормированы на **собственный реальный размах** — вес 0 в реальном минимуме,
вес 1 в реальном максимуме (решение option B).

## 3. Численный пример (дефолты: −25 % несущей, −50 % биений)

> **Нормировка option B.** Веса считаются по **реальному размаху кривой**,
> а не по объявленному `carrierRange` и не от нуля для биений (см. §2.1/§2.3).
> В таблицах экстремумы осей (`carrierLo/Hi`, `beatLo/Top`) взяты по
> минимуму/максимуму **показанных здесь** точек кривой — для иллюстрации
> достаточно; в коде они сэмплируются по всем 720 точкам суток.

### «Циркадный ритм» — несущая 174…440 Гц, `|beat|` 3…25 Гц

| Время | carrier | w_c | эфф. снижение несущей | beat | w_b | эфф. снижение биений | Итог на дне впадины |
|---|---|---|---|---|---|---|---|
| 00:00 | 174 | 0.000 | **0 %** | 3 | 0.000 | **0 %** | 174.0 Гц / 3.00 Гц — ночь не трогаем (ровно 0) |
| 06:00 | 220 | 0.173 | −4.3 % | 8 | 0.227 | −11.4 % | 210.5 Гц / 7.09 Гц |
| 09:00 | 440 | 1.000 | −25 % | 20 | 0.773 | −38.6 % | 330.0 Гц / 12.3 Гц |
| **12:00** | 440 | 1.000 | **−25 %** | 25 | **1.000** | **−50 %** | **330.0 Гц / 12.5 Гц — бета→альфа** |
| 18:00 | 250 | 0.286 | −7.1 % | 12 | 0.409 | −20.5 % | 232.1 Гц / 9.55 Гц |

Смысл виден сразу: днём впадина уводит пульсацию из беты в альфу (25 → 12.5 Гц),

Именно это и есть требуемое угасание (вес 0 в реальном минимуме, решение option B).

## 4. Жёсткие правила

### R1. Вес считается ТОЛЬКО по базовой кривой

`carrier_base(t)` и `beat_base(t)` — кривые **до** наложения расслабления
(объект `baseCurve` внутри `generateRelaxationTrapezoidPoints`). Не по
`curveWithRelaxation`, не по предыдущему кадру.

Иначе петля: расслабление снижает частоту → вес падает → снижение слабее →
частота выше → вес растёт. Результат недетерминирован и зависит от порядка
пересчёта. Прямое следствие: **`w` — чистая функция пресета и настроек**,
одинаковая в UI, в движке и в тестах.

### R2. Вес берётся в собственной точке времени

`w` для точки `t2` считается по `carrier_base(t2)` / `beat_base(t2)`, для `t3` —
по значениям в `t3`. Никаких «один вес на весь период».

Следствие: если базовая кривая за время плато уехала, **дно впадины
наклоняется чуть сильнее**, чем сегодня. Это не дефект, а продолжение текущего
поведения: `t2` и `t3` и сейчас считаются от значений базовой кривой в свои
моменты времени, то есть плато уже повторяет её дрейф. Угасание добавляет к
этому дрейфу плавную модуляцию глубины.

### R3. Точки `t1`/`t4` не трогаются

Они и так лежат на базовой кривой (снижение 0, умножение на что угодно даёт 0).
Правило нужно, чтобы не было соблазна «оптимизировать»: именно неизменность
`t1`/`t4` гарантирует, что период **закрывается ровно на базовом уровне** и на
стыке с соседними участками нет ни разрыва, ни ступеньки (ср.
`design_relaxation_beat_gate.md` §4.2).

### R4. Вырожденная опора → угасание инертно (`w = 1`), а не «выключить»

| Опора | Условие | `w` | Почему |
|---|---|---|---|
| несущая | `carrierSpan = carrierHi − carrierLo <= FADE_SPAN_EPS` | 1 | реальный размах выродился (плоская несущая); молча гасить фичу нельзя |
| биения | `beatSpan = beatTop − beatLo <= FADE_SPAN_EPS` | 1 | реальный размах выродился (плоские биения); выбрано 1, чтобы не делить на ноль |

> Под вырождение теперь попадает **плоская кривая** (а не нулевая ширина
> объявленного `carrierRange`) — ровно это состояние нового пресета
> (`newPresetCurve()` из одной точки). Option B сделал плоскую несущую
> инертной (`w ≡ 1`), что раньше давало бы `w = 0` и «убивало» режим.

Общий принцип: **в неопределённой ситуации угасание отключается, а не
выключает расслабление.** Обратное («w = 0, фича молча ничего не делает») —
ровно тот класс багов, который потом невозможно диагностировать.

### R5. Гомотопия: угасание не создаёт НИ ОДНОГО нового ограничения

Это главное structural-свойство фичи, и оно делает реализацию почти
бесплатной. Зафиксируем точку и будем менять `w` от 0 до 1.

Шаг 1, снижение:

```
rawCarrier(w) = carrier · (1 − R_c · w),   R_c ∈ [0; 1]
rawBeat(w)    = beat    · (1 − R_b · w),   R_b ∈ [0; 2]
```

- `1 − R_c·w ∈ [0; 1]` ⇒ `rawCarrier(w) ∈ [carrier·(1−R_c); carrier]`;
- `1 − R_b·w ∈ [−1; 1]` ⇒ `|rawBeat(w)| <= |beat|` при любом `w`
  (максимум модуля достигается на концах: `|beat|` при `w=0` и
  `|beat|·|1−R_b| <= |beat|` при `w=1`).

То есть **на пути от базовой точки к полностью сниженной ни carrier не выходит
за `[база·(1−R_c); база]`, ни модуль биений не превышает исходного**.

Шаг 2, пол частоты канала: `carrierForFloor = floor + |rawBeat(w)|/2`
считается по **тому же** `rawBeat(w)`, поэтому

```
reducedCarrier >= floor + |rawBeat(w)|/2
   ⇒  2·(reducedCarrier − floor) >= |rawBeat(w)|
   ⇒  кламп модуля биений (шаг 4) НЕ СРАБАТЫВАЕТ НИ ПРИ КАКОМ w
```

И сегодня он не срабатывает ровно по той же причине; угасание эту гарантию не
ослабляет, а шаг 3 (`.coerceAtMost(carrier)`) и абсолютный пол `floor`
выполняются по построению.

**Следствие для реализации: `reduceFrequencies` менять не нужно вообще.** Она
уже принимает глубину параметром; угасание меняет только то, какое значение
туда передают. Все существующие защиты остаются корректными без правок.

### R6. `w = 0` — тождественное преобразование

При `w_c = w_b = 0`: `rawCarrier = carrier`, `rawBeat = beat`,
`reducedCarrier = max(carrier, floor+|beat|/2, floor).coerceAtMost(carrier) = carrier`,
кламп биений не срабатывает (точка внутри графика ⇒ `|beat| <= 2·(carrier−floor)`).

Значит, **в мёртвой зоне виртуальная точка в точности равна базовой**, и период
вырождается в четыре коллинеарные точки на самой базовой кривой. Кривая там
становится ровно базовой (у Catmull-Rom и monotone-сплайна коллинеарные точки
дают прямую — overshoot не возникает), а не «почти базовой».

Отсюда же правило: **точки `t2`/`t3` издаются всегда**, даже при `w = 0`.
Во-первых, это делает совпадение с базовой кривой точным (иначе между `t1` и
`t4` мы интерполировали бы «мимо» узлов базовой кривой). Во-вторых, код
остаётся без ветвлений.

### R7. Знак биений при `beatReductionPercent > 100 %`

Свыше 100 % снижение уходит за ноль и инвертирует раскладку каналов. Угасание
гасит **весь эффект целиком, включая инверсию**: при `w → 0` результат
`beat·(1 − R_b·w) → beat`, то есть исходный знак и исходный модуль. Промежуточные
`w` дают непрерывный переход тон → затухание → инверсия, и R5 гарантирует, что
модуль нигде не превысит исходного. Отдельной обработки знака не требуется.

### R8. Угасание выключено ⇒ ноль дополнительной работы

Сэмплирование кривой для `beatTop` выполняется **только** при
`fadeByRangePosition = true`. Существующие пресеты (опция по умолчанию
выключена) не платят ничего, и их точки остаются **побитово прежними**.

## 5. Что меняется на слуху и на графике

- **На слуху:** глубина впадин получает суточный профиль. Переходы остаются на
  тех же местах и той же длительности — меняется только «амплитуда» провала.
  Никаких новых щелчков: смена кривой идёт через zero-overlap handoff, как и
  любая другая правка настроек.
- **На графике:** впадины становятся разной глубины — у дна графика
  распрямляются в линию. Мини-график в списке пресетов покажет это сразу, но
  **только если ключ кэша учитывает новый флаг** (§6.4) — иначе геометрия
  залипнет старой.
- **Побочный эффект, который стоит проверить глазами:** при `w ≈ 0` соседние
  периоды «схлопываются» в базовую кривую, и визуально ритм впадин кажется
  рваным (глубокий — мелкий — глубокий). Это и есть задуманное поведение, но
  на крайних настройках (−100 % несущей при узком диапазоне) стоит посмотреть,
  не выглядит ли это как баг.

## 6. Что менять в коде

Всё считается в Котлине: `NativeAudioEngine.updateConfig` вызывает
`relaxationSettings.generateVirtualPoints(curve)` и отдаёт готовые точки в C++.
**Нативную часть трогать не нужно.**

### 6.1 Модель — `core/audio/.../model/BinauralPreset.kt`

Новое поле `RelaxationModeSettings`:

```kotlin
/**
 * Угасание периодов расслабления по положению частот в диапазоне.
 *
 * ВКЛ: глубина снижения каждой виртуальной точки умножается на вес — близость
 * частоты к верхней границе СВОЕГО диапазона. Оси считаются НЕЗАВИСИМО:
 *
 *   w_carrier = clamp((carrier_base − carrierLo) / (carrierHi − carrierLo), 0, 1)   // реальный размах несущей
 *   w_beat    = clamp((|beat_base| − beatLo) / (beatTop − beatLo),           0, 1)   // реальный размах модуля биений
 *
 * Обе оси нормированы на СОБСТВЕННЫЙ РЕАЛЬНЫЙ РАЗМАХ базовой кривой
 * (carrierMagnitudeExtremes / beatMagnitudeExtremes). Вес 0 в реальном
 * минимуме, вес 1 в реальном максимуме (решение option B, см. §2.1/§2.3).
 * Объявленный carrierRange НЕ используется: у него есть запас снизу, из-за
 * которого в реальном минимуме получалось ненулевое снижение. Хранимый
 * beatRange равен ±1000 Гц и нормировкой не служит (см. §2.2). Мера — модуль:
 * знак beat задаёт раскладку каналов, а не уровень возбуждения.
 *
 * У верхней границы слайдеры работают в полную силу, у нижней период
 * расслабления вырождается в базовую кривую (R6).
 *
 * Вес берётся ТОЛЬКО по базовой кривой (R1) — иначе возникает петля
 * «снизили → вес упал → снижение ослабло».
 *
 * Вырожденная опора (нулевая ширина диапазона, биения тождественно 0)
 * даёт w = 1: угасание отключается, а не глушит режим (R4).
 */
val fadeByRangePosition: Boolean = false
```

Дефолт `false` — существующие пресеты обязаны звучать как раньше (и R8 делает
это бесплатным). `require` не нужен, это `Boolean`.

`generateRelaxationTrapezoidPoints` — два места. До цикла:

```kotlin
val carrierLo: Float
val carrierSpan: Float
val beatLo: Float
val beatTop: Float
if (fadeByRangePosition) {
    val (cLo, cHi) = CurveSampling.carrierMagnitudeExtremes(curve)
    val (bLo, bHi) = CurveSampling.beatMagnitudeExtremes(curve)
    carrierLo = cLo; carrierSpan = cHi - cLo
    beatLo = bLo; beatTop = bHi
} else {
    carrierLo = 0.0f; carrierSpan = 0.0f; beatLo = 0.0f; beatTop = 0.0f
}
```

И в точках `t2`/`t3` (сейчас туда передаются `carrierReduction`/`beatReduction`):

```kotlin
val (wc, wb) = fadeWeights(
    carrier = curve.getCarrierFrequencyAt(time2),
    beat = curve.getBeatFrequencyAt(time2),
    carrierLo = carrierLo, carrierSpan = carrierSpan,
    beatLo = beatLo, beatTop = beatTop
)
val (carrier2, beat2) = reduceFrequencies(
    curve.getCarrierFrequencyAt(time2),
    curve.getBeatFrequencyAt(time2),
    carrierReduction * wc,
    beatReduction * wb,
    curve.carrierRange.min
)
```

`carrierLo/carrierSpan/beatLo/beatTop` считать **один раз** на вызов, не на
точку (сэмплирование кривой — только при `fadeByRangePosition`, R8).

Сам вес — `internal fun` (виден тестам), одна функция на обе оси:

```kotlin
internal fun fadeWeights(
    carrier: Float, beat: Float,
    carrierLo: Float, carrierSpan: Float,
    beatLo: Float, beatTop: Float
): Pair<Float, Float> {
    if (!fadeByRangePosition) return 1.0f to 1.0f
    val wCarrier = if (carrierSpan > FADE_SPAN_EPS) {
        ((carrier - carrierLo) / carrierSpan).coerceIn(0.0f, 1.0f)
    } else 1.0f
    val beatSpan = beatTop - beatLo
    val wBeat = if (beatSpan > FADE_SPAN_EPS) {
        ((abs(beat) - beatLo) / beatSpan).coerceIn(0.0f, 1.0f)
    } else 1.0f
    return wCarrier to wBeat
}
```

Константа: `FADE_SPAN_EPS = 1e-3f` (одна на обе оси; вырожденный размах →
`w = 1`, R4). `FadeWeight` data-класс упразднён — возвращается `Pair<Float, Float>`.

`reduceFrequencies` — **без изменений** (см. R5). Подпись уже принимает глубину
параметром, что и требовалось.

### 6.2 Вспомогательный примитив — новый файл `model/CurveSampling.kt`

```kotlin
/**
 * Экстремумы модуля частоты биений на интерполированной кривой.
 *
 * Сэмплами, а не по узлам: при CARDINAL сплайн вылетает за пределы узлов
 * (overshoot), и «максимум по точкам» занизил бы потолок.
 *
 * [sampleCount] делит сутки нацело (86400 = 720 · 120), точка 86400 ≡ 0
 * периодична и отдельного сэмпла не требует.
 *
 * Возвращает ПАРУ — минимум пригодится ограничителю территории
 * (docs/design_relaxation_beat_gate.md, порог mMin + p·(mMax−mMin)), чтобы не
 * сэмплировать кривую дважды.
 */
object CurveSampling {
    const val DEFAULT_SAMPLE_COUNT = 720          // шаг 120 с = 2 мин

    fun carrierMagnitudeExtremes(
        curve: FrequencyCurve,
        sampleCount: Int = DEFAULT_SAMPLE_COUNT
    ): Pair<Float, Float> {
        val step = 86400 / sampleCount
        var min = Float.POSITIVE_INFINITY
        var max = 0.0f
        for (i in 0 until sampleCount) {
            val magnitude = curve.getCarrierFrequencyAt(LocalTime.fromSecondOfDay(i * step))
            if (magnitude < min) min = magnitude
            if (magnitude > max) max = magnitude
        }
        return min.coerceAtLeast(0.0f) to max
    }

    fun beatMagnitudeExtremes(
        curve: FrequencyCurve,
        sampleCount: Int = DEFAULT_SAMPLE_COUNT
    ): Pair<Float, Float> {
        val step = 86400 / sampleCount
        var min = Float.POSITIVE_INFINITY
        var max = 0.0f
        for (i in 0 until sampleCount) {
            val magnitude = abs(curve.getBeatFrequencyAt(LocalTime.fromSecondOfDay(i * step)))
            if (magnitude < min) min = magnitude
            if (magnitude > max) max = magnitude
        }
        return min.coerceAtLeast(0.0f) to max
    }

    fun beatMagnitudeCeiling(
        curve: FrequencyCurve,
        sampleCount: Int = DEFAULT_SAMPLE_COUNT
    ): Float = beatMagnitudeExtremes(curve, sampleCount).second
}
```

**Точность здесь не критична**, и это стоит понимать: `carrierHi`/`beatTop`
задают не границу, а **усиление**. Недолёт вниз означает лишь, что у пика
несколько точек насытятся на `w = 1` — это самоисправляется клампом, бисекция и
уточнение границы (как в §4.6 gate-документа) не нужны. Минимумы (`carrierLo`/
`beatLo`) тоже берутся сэмплами, поэтому в реальном минимуме вес гарантированно
0 (решение option B). `N = 720` выбран не по точности, а чтобы переиспользовать
хелпер в будущем ограничителе; для самого угасания достаточно и 288.

Стоимость: 720 интерполяций `O(log n)` — десятки микросекунд, вызов只在 смене
настроек (`NativeAudioEngine.updateConfig`, поток `BinauralWriter-N`).

## 7. Тесты — `core/audio/src/test/.../RelaxationRangeFadeTest.kt`

1. **Выключено ⇒ побитово как раньше.** Точки с `fade = false` и точки
   «старого» генератора совпадают по времени, carrier и beat (золотой список).
2. **Реальный минимум кривой ⇒ 0 (option B).** `carrierAtCurveMinimumIsNotReduced`:
   плато ровно на реальном минимуме несущей (`carrierLo`) даёт `carrier` без
   изменений; при `|beat| = beatLo` — `beat` без изменений. **Не** по
   `carrierRange.min` (у объявленного диапазона есть запас снизу).
3. **Реальный максимум кривой ⇒ полная глубина.** `carrierAtCurveMaximumGetsFullDepth`:
   плато на реальном максимуме несущей (`carrierHi`) и на пике `|beat|`
   (`beatTop`) даёт ровно `carrierReductionPercent` / `beatReductionPercent`
   (с учётом существующих полов).
4. **Монотонность весов.** `weightsGrowWithPositionInRange`: прямой вызов
   `fadeWeights` по обеим осям — при росте `carrier` и `|beat|` веса не убывают,
   от 0 на реальном минимуме до 1 на реальном максимуме.
5. **Тождественность при `w = 0` (R6).** `zeroWeightReproducesTheBaseCurveExactly`:
   плато на реальном минимуме несущей при `beat ≡ beatLo` — виртуальная точка
   **равна** базовой с точностью `eps`, а не «примерно равна».
6. **Гомотопия (R5).** Для набора пресетов и настроек: при любом
   `w ∈ [0; 1]` (включая инверсию `beatReduction = 200 %`) результат лежит
   между базовой точкой и полностью сниженной, `reducedCarrier >= floor`,
   `reducedCarrier <= carrier_base`, `|beat| <= |beat_base|`, нижний канал не
   уходит ниже `floor`.
7. **Плоская кривая биений** (в том числе `newPresetCurve()` из одной точки) ⇒
   `w_beat ≡ 1`, поведение как без угасания (R4).
8. **Биения тождественно 0** ⇒ без исключений, без NaN, `w_beat = 1`.
9. **Вырожденный реальный размах несущей** (`carrierLo == carrierHi`) ⇒ без
   деления на ноль, `w_carrier = 1` (R4).
10. **CARDINAL-overshoot выше сэмплированного максимума** ⇒ `w` клампится в 1,
    границы каналов не нарушены.
11. **Знак биений.** При `beatReduction <= 100 %` знак сохранён при любом `w`;
    при `150 %` и `w = 1` знак инвертирован, при малых `w` — сохранён, переход
    непрерывен (R7).
12. **Детерминизм (R1).** Двойной вызов генератора с одним пресетом даёт
    одинаковые точки; результат не зависит от того, включено ли угасание в
    предыдущем кадре.
13. **Геометрия не поехала.** Времена точек, число периодов, длительности
    переходов и пауз — те же, что с выключенным угасанием; отличаются только
    значения частот (R3).
14. **Инвариант `t1`/`t4`.** Первая и последняя точки каждого периода равны
    базовому значению кривой в свои моменты времени.
15. **Прямая нормировка `fadeWeights` на реальный размах.**
    `fadeWeightsNormalizesToRealExtent`: 0 на реальном минимуме обеих осей, 1 на
    максимуме, 0.5 посередине, кламп вне диапазона.
16. **Вырожденный размах ⇒ `w = 1`.** `fadeWeightsDegenerateExtentFallsBackToFull`:
    при `carrierSpan <= FADE_SPAN_EPS` или `beatSpan <= FADE_SPAN_EPS` обе оси
    возвращают 1 (R4, угасание инертно, а не выключено).
17. **Выключено ⇒ `(1, 1)`.** `fadeWeightsDisabledReturnsFull`: при
    `fadeByRangePosition = false` `fadeWeights` возвращает `1.0f to 1.0f`
    независимо от аргументов (R8).

## 8. Открытые вопросы

### 8.1 Опора обеих осей: реальный размах кривой (решение option B, реализовано)

Первоначально для несущей была выбрана нормировка на ОБЪЯВЛЕННЫЙ
`carrierRange`, а для биений — на `[0; mMax]` (аргументы ниже). В ходе
реализации **обе оси переведены на реальный размах базовой кривой**
`[min; max]`: несущая — `[carrierLo; carrierHi]`, биения — `[beatLo; beatTop]`
(см. §2.1/§2.3). Причина — пользователь заметил, что при нормировке на
объявленный диапазон/нуль реальный минимум давал ненулевое снижение (−4 % / −6
%) вместо требуемого 0. Это **решение option B**, выбранное явно.

Альтернативы, рассматривавшиеся ранее (оставлены для истории):

- **`[mMin; mMax]` (размах самой кривой)** — **ТЕПЕРЬ ВЫБРАН** (обе оси).
  Использует весь динамический диапазон: самый спокойный момент получает ровно
  0, самый бурный — ровно слайдер. Плоская кривая требует правила — закрыто
  R4 (`w ≡ 1`); пресет 2…4 Гц получает разброс 0→100 % на 2 Гц — приемлемо;
  правка любого участка пере масштабирует шкалу — видно на графике.
- **`[0; mMax]` (дно — 0 Гц)** — **отвергнут**: давал ненулевое снижение в
  реальном минимуме, что пользователь посчитал ошибкой.
- **Абсолютная шкала** (0…40 Гц) — **отвергнут**: на пресете из дельты фича
  молча ничего не делает.

Переход обратно на `[0; mMax]` или абсолютную шкалу для биений меняет ровно
одну строку в `fadeWeights` (`beatLo = 0.0f` или другой потолок).

### 8.2 Линейная шкала или логарифмическая?

Принято линейно. Аргумент: `w_carrier` — это **высота точки на нарисованном
графике**, правило видно глазами. Логарифмическая шкала ближе к слуху (высота
тона воспринимается по логарифму) и подняла бы `w` в середине диапазона: для
174 Гц в диапазоне 100…600 линейно 0.148, логарифмически 0.31.

Если после практики покажется, что в нижней половине графика угасание «душит»
фичу сильнее нужного, дешёвый вариант — показатель формы (§8.3), дорогой —
переход на логарифм.

### 8.3 Показатель формы γ

`w = u^γ`: γ > 1 концентрирует эффект у верхней границы, γ < 1 поднимает
глубину в середине диапазона (например, γ = 0.5 даёт для 174 Гц в диапазоне
100…600 вес 0.38 вместо 0.148).

Пока **не вводить**: это третий параметр, смысл которого («нелинейность
угасания») тяжело объяснить в один подпись. Если понадобится — это одно поле и
один `pow` в `fadeWeight`, ломающего изменения нет.

### 8.4 Как ужиться с `beatGatePercent`

Обе фичи смотрят на `|beat|`, но отвечают на разные вопросы: gate — **где**
ставить периоды (порог `mMin + p·(mMax−mMin)`), fade — **насколько глубоко**
(вес `|beat|/mMax`). Композиция проста: gate режет территорию, fade
масштабирует глубину внутри неё; умножение с коэффициентом усечения последнего
периода из §4.2 gate-документа:

```
R = R_slider · k_truncation · w_fade
```

Разные опоры у одной величины (gate и fade оба берут `mMin`/`mMax` из
`CurveSampling.beatMagnitudeExtremes`, но употребляют по-разному) не ошибка, а
следствие разных задач: порогу нужна привязка к минимуму, чтобы `p=0`
означало «везде», а весу — привязка к реальному минимуму, чтобы в самом
спокойном моменте угасание давало ровно 0 (option B). Одного прохода по кривой
хватает на двоих.

### 8.5 Показывать ли эффективную глубину?

Подпись вида «на пике −17 % / −50 %, в минимуме −4 % / −6 %» была реализована
(`RelaxationModeSettings.fadeDepthSummary` / класс `FadeDepthSummary`) и затем
**удалена** по решению пользователя. Причина: при первоначальной нормировке на
объявленный диапазон/нуль эти числа оказались неверными — «в минимуме −4 % /
−6 %» противоречило замыслу «0 на дне», сбивало пользователя и выглядело как
баг. Подпись, которая врёт, хуже её отсутствия.

Если вернуть — после option B (нормировка на реальный размах) «в минимуме»
будет ровно 0 % / 0 %, а «на пике» — ровно слайдер; честная подпись возможна,
но пока не реализуется (пользователь предпочёл не показывать производные
числа вовсе).

### 8.6 Нужен ли «пол» интенсивности?

Постановка требует 0 на дне диапазона, и это реализовано. Но полностью
исчезающий период — крайность: если пользователь хочет «везде хоть немного»,
придётся завести `fadeFloorPercent` (вес не ниже, например, 20 %). Пока не
заводим: сценарий не виден, а поле сразу усложняет и модель, и подпись.
