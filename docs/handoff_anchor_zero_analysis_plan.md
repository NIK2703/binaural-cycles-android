# Анализ: возобновление с 0:00 при быстрых перезапусках в редакторе пресета

Дата: 2026-09-01
Статус: корневая причина подтверждена логом устройства; документ содержит только
анализ, план работ, план тестирования и целевую модель. Код не изменён.

---

## 1. Симптом

При редактировании пресета (перетаскивание точки кривой туда-сюда → поток
изменений `SETTINGS`) воспроизведение внезапно «перепрыгивает» на **00:00**
и далее **не восстанавливается** само: каждый следующий перезапуск снова
стартует с 00:00.

## 2. Воспроизведение и доказательства

Воспроизведено штормовым прогоном `tools/dbgxfade.sh` (фазы D–K: серии
переключений пресета и pause/preset/resume). Лог: `xfade_run3.log`.

Факты из лога:

- spec#2…#8: `beginHandoff … (curveTod=45409.0 … 45452.0)` — корректные якоря.
- **Начиная со spec#9 и до конца прогона: `curveTod=0.0`** — 21 из ~36
  подготовок потока получили `якорь кривой=0 (явный=true)`.
- Момент перелома (spec#8 → spec#9):

```
12:37:33.583 prepare spec#8 … curveTime=45452
12:37:33.625 prepare spec#8: якорь кривой=45452 (явный=true)
12:37:33.655 start spec#8 …
12:37:33.672 launchStream: start spec#8 успешно, fade-in идёт
12:37:33.672 beginHandoff spec#9 … (curveTod=0.0, …)   ← та же миллисекунда
```

Изменение пришло во **FADE_IN**, спустя ~20–90 мс после `prepare()`, до первого
опроса частот UI — и захват непрерывности вернул 0.

Защёлкивание: spec#9 якорится на 0 → его собственный кэш UI-времени ≈ 0 →
следующий захват снова читает 0 → цепочка 0 → 0 → … необратима без
переустановки состояния.

## 3. Корневая причина

Цепочка чтения позиции при захвате непрерывности:

`BinauralStreamManager.captureContinuity()`
→ `BinauralStreamImpl.getCurrentCurveTimeSeconds()`
→ `nativeEngine?.getCurrentTimeOfDay()?.toFloat() ?: 0f`
→ JNI `nativeGetCurrentTimeOfDay` → `BinauralEngine::getCurrentTimeOfDaySeconds()`:

```cpp
if (m_uiAnchorWallMs.load() != 0) {
    return static_cast<int32_t>(m_uiLastUiTimeSec.load());  // ← КЭШ
}
return getCurrentTimeSeconds();
```

Дефект в **несогласованности записи кэша**:

- `m_uiLastUiTimeSec` пишется **только** в `computeUiTimeSeconds()`, которая
  вызывается из `getFrequenciesAtCurrentTime()` — то есть только опросом UI.
- `anchorUiTimeline(start, end)` ставит `m_uiAnchorWallMs`, но **не** пишет
  `m_uiLastUiTimeSec`.
- Порядок в `prepare()`: `resetState()` (оба поля = 0) → `setCurveTime(t)`
  (ставит `m_uiAnchorWallMs = now`, кэш остаётся 0).

Итоговое окно: между `start()` свежего потока и первым опросом частот UI
геттер видит «якорь установлен» и возвращает **протухший кэш = 0** вместо
реального времени суток. Окно ~20–100 мс; при частых правках хендоверы идут
вплотную, и вероятность попадания в окно быстро приближается к 1.

### Сопутствующие дефекты (усиливают / делают необратимым)

1. **Kotlin `?: 0f`** — второй независимый источник литерального 0: когда
   `nativeEngine == null` (разрушение потока), `getCurrentCurveTimeSeconds()`
   тоже возвращает 0.
2. **Нет валидации якоря**: `prepare()` безусловно принимает любой
   `resumeCurveTimeSeconds >= 0` как «явный якорь»; 0 (полночь) неотличим от
   мусора.
3. **Протухание по времени**: якорь захватывается в момент `beginHandoff`, а
   применяется после полного релиза старого потока и `prepare()` нового —
   без проверки свежести.
4. **Нарушение инварианта даже в «правильном» пути**: хендовер якорит новый
   поток на **замороженную позицию старого**, а не на «сейчас». Захват
   отстаёт от настенных часов на длительность хендовера (~0.3–1 с), следующий
   захват читает уже отстающую позицию — **лаг копится** с каждой правкой
   (в логе spec#8: стена 12:37:33 = 45453 с, якорь 45452 — уже −1 с за 7
   хендоверов). Звук систематически отстаёт от «сейчас», что противоречит
   инварианту приложения.

## 4. План работ

### P0 — горячее исправление (минимальный diff, снимает баг и защёлкивание)

1. **Натив: согласовать кэш с якорем.**
   - В `anchorUiTimeline(startSec, endSec)` дополнительно писать
     `m_uiLastUiTimeSec.store(startSec)` — кэш всегда консистентен с якорем.
   - Усиление: `getCurrentTimeOfDaySeconds()` при установленном якоре должен
     **вычислять** время той же логикой, что `computeUiTimeSeconds()`
     (span=0 → вернёт `startSec`), а не читать сырой кэш. Кэш нужен лишь для
     «заморозки» UI на паузе.
2. **Kotlin: убрать `?: 0f`.** В `getCurrentCurveTimeSeconds()` при
   `nativeEngine == null` возвращать `spec.realTimeOfDaySeconds()` (часы уже
   DebugClock-совместимы) — никогда не эмитировать литеральный 0.
3. **Валидация якоря на границе.** В `captureContinuity()` /
   `enrichForContinuity()`: если `|normalize(anchor − now)| > ε`
   (ε ≈ 5 с, нормализация через `((x % 86400)+86400)%86400` — ловит полночь),
   считать якорь недействительным → `-1` (якорь на «сейчас» в `prepare()`) +
   WARN-лог. 0 при `now ≫ 0` всегда отбрасывается; защёлкивание невозможно.

### P1 — структурное (устраняет класс ошибок)

4. **Хендовер якорит на «сейчас».** Для `SETTINGS` / `PRESET_SWITCH` новый
   поток якорится на `now` в момент `prepare()` (`resumeCurveTimeSeconds = -1`),
   а не на замороженную позицию старого. От уходящего потока нужна **только
   фазовая непрерывность** (уже передаётся отдельно:
   `switchLeftPhase/switchRightPhase`). Скачок позиции кривой при этом ≤
   длительности хендовера (< 1 с кривой) — для гладкой кривой неразличимо,
   а инвариант «звук = сейчас» выполняется точно и без накопления лага.
   `captureContinuity()` перестаёт читать время кривой вовсе.
5. **Якорь как значение с происхождением**, а не голый `Float?`:
   `{ valueSec, source: CAPTURED | NOW | FALLBACK, capturedAtMs }` внутри
   спеки; сентинел «нет якоря» — только `-1`; `0` — легальная полночь.
   Удалить поле `switchCurveTod` из менеджера (источник рассинхрона).
6. **Ужесточение автомата состояний**: захват непрерывности разрешать только
   из состояний `{FADE_IN, RUNNING, PAUSED}` и только от потока с живым
   движком; окна «`current` жив, движок мёртв» покрывать явным состоянием.

### P2 — верификация

7. Юнит-тесты (натив + Kotlin), интеграционные штормы на устройстве,
   сторож инварианта — см. раздел 5.
8. Прогон всех существующих сьютов (`tools/dbgverify_resume.sh`,
   `tools/dbgxfade.sh`) + soak.

## 5. План тестирования (этот и смежные случаи)

### 5.1 Юнит, натив (host-харнес)

| # | Тест | Ожидание |
|---|------|----------|
| N1 | `resetState() → setCurveTime(T) → getCurrentTimeOfDaySeconds()` **сразу**, без опроса UI | ≈ T, **не 0** (регрессия корневой причины) |
| N2 | После `anchorUiTimeline(S,E)` кэш UI == S | консистентность записи |
| N3 | То же через границу полуночи (T = 86399.9, сдвиг +0.2 с) | нормализация, нет отрицательных/86400+ |
| N4 | Пауза: UI-время заморожено, `getCurrentTimeOfDaySeconds()` не «убегает» | freeze по замкнутому span |

### 5.2 Юнит, Kotlin (менеджер, фейковый поток)

| # | Тест | Ожидание |
|---|------|----------|
| K1 | Изменение во **FADE_IN** (≤ 100 мс после start) | следующий `resumeCurveTimeSeconds ≈ now`, **никогда 0** при `now ≠ 0` |
| K2 | Изменение в окне «движок разрушен» | фолбэк на `now`, никогда 0 |
| K3 | Липкий-0: принудительно подать один плохой захват | валидация отбрасывает, цепочка восстанавливается на `now` |
| K4 | Хендовер не копит лаг: серия из 20 правок | `|anchor − now| ≤ ε` на каждом шаге (после P1 — тождественно now) |
| K5 | Полночь: правка при `now = 86399.9` | якорь 0 корректен и НЕ отбрасывается валидацией |

### 5.3 Интеграция на устройстве (расширить `tools/dbgxfade.sh` или `tools/dbganchor.sh`)

- **S1. Шторм FADE_IN** (точное окно бага): длинный fade-in, повторный `switch`
  через 20–50 мс после `start`; 50 итераций. Утверждения:
  `audible − now ∈ ±2 с` всегда; в логе **нет** `curveTod=0` при `now ≫ 0`;
  нет защёлкивания после прогона.
- **S2. Шторм правок «туда-сюда»** (сценарий пользователя): чередование двух
  пресетов с интервалом 100–300 мс, 5 мин. Те же утверждения + лаг не растёт.
- **S3. Восстановление**: принудительно увести кривую в 0 (debug-scrub),
  затем правка → якорь возвращается на `now`.
- **S4. Полуночный рубеж** (через `warp`/`totime`): правки вокруг 00:00.
- **S5. Совместный шторм**: правки + pause/resume + смена интервала буфера.

### 5.4 Сторож инварианта (generic, ловит весь класс)

Debug-фоновая задача: каждые ~500 мс снимать `vsnap`, сравнивать
`audible` vs `now`; при `|Δ| > 2 с` дольше 3 с подряд — ERROR-лог с контекстом
(state/spec/anchor). Включать в длительных soak-прогонах.

## 6. Надёжная модель приложения

### 6.1 Принципы

1. **Единственный источник «сейчас»**: одни часы на сторону
   (`PlaybackSpec.realTimeOfDaySeconds()` в Kotlin, `realTimeOfDaySeconds()`
   в нативе; обе уже DebugClock-осведомлены). Любое решение о якоре —
   производное от них, вычисленное **в последний ответственный момент**
   (в `prepare()`), а не захваченное заранее.
2. **Инвариант явен и enforced на границах**: «слышимая позиция кривой ==
   now (± ε)». Ни один путь не может ввести абсолютный якорь в обход
   валидации.
3. **Валидация всего внешнего**: любой якорь, пришедший извне (захват,
   восстановление сессии, debug-команда), проверяется
   `|normalize(a − now)| ≤ ε`; нарушение → фолбэк на now + лог. Полночь
   обрабатывается нормализацией, а не особыми случаями.
4. **Никаких перегруженных сентинелов**: «нет якоря» = `-1`, и только он.
   `0` — легальное время суток. Запрещены фолбэки вида `?: 0f`.
5. **Консистентность записи кэша**: любая функция, меняющая якорь, обязана
   атомарно обновлять и производный кэш; геттеры не читают кэш, который может
   протухнуть относительно своего стража.
6. **Семантика хендовера**: для правок кривой/настроек новый поток якорится
   на now; от уходящего потока наследуются **только фазы** (и громкость).
   Это делает инвариант точным и убирает канал протухшего захвата целиком.
7. **Наблюдаемость**: каждый якорь логируется с происхождением
   (`source=capture|now|fallback`), `vsnap` остаётся машинным снимком,
   сторож инварианта — постоянной проверкой.

### 6.2 Поток данных (целевой)

```
UI-правка → buildSpec(SETTINGS)              → спека БЕЗ якоря (-1)
           → actor: requestHandoff
           → fadeOutCurrent(SWITCH)          (фазы старого — в спеку NEXT)
           → onStreamFullyStopped → launchSpec
           → prepare(): anchor = now()        ← единственная точка якорения
           → валидация (тривиальна: anchor == now)
           → setCurveTime(anchor) + фазы     → play(preserveTimeline)
```

Пауза/возобновление — отдельный, уже покрытый решатель (`SOFT/REBUILD_*`);
он не меняется, но его якорь проходит ту же валидацию.

### 6.3 Что это устраняет

- Протухший кэш UI-времени (P0.1) — больше не читается неконсистентно.
- Литеральный 0 из Kotlin-фолбэка (P0.2).
- Мусорный/протухший якорь (P0.3, P1.5) — отбрасывается на границе.
- Накопление лага по серии правок (P1.4) — якорь всегда now.
- Защёлкивание 0 → 0 (P0.3 + P1.4) — невозможно по построению.

## 7. Риски и смежные замечания

- P0.1 трогает нативный геттер, который читает и UI-индикатор: после правки
  индикатор и частоты останутся согласованными (та же формула), но прогнать
  визуальную проверку экрана «Сейчас» обязательно.
- K5/S4 критичны: валидация не должна отбрасывать **легальную** полночь —
  только «далёкий от now» якорь.
- Существующие сьюты `dbgverify_resume.sh` (9/9) должны остаться зелёными —
  пауза/возобновление затрагивается только валидацией якоря.
