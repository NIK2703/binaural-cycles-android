# Ограничитель применения периодов расслабления (`beatGatePercent`)

**Статус:** проект решения, код не писался.
**Цель:** слайдер 0–100%, который отвечает на вопрос «НА КАКИЕ отрезки графика
накладывать периоды расслабления»: 0% — на весь график, 100% — ни на что,
50% — только на отрезки, где частота биений выше середины диапазона графика.

---

## 1. Формула порога: буквальная формулировка не сходится

Пользователь описал порог как «p% от разницы между наибольшей и наименьшей
частотой биения». Возможны два прочтения:

| | Формула | Проверка на p=0 | Проверка на p=100 |
|---|---|---|---|
| **(A)** буквальная | `T = p · (max − min)` | `T = 0` → «применять где beat > 0». Для пресета с положительным beat это случайно даёт весь график, но для знакового beat (−20…+20) — только половину суток ✗ | `T = max − min` → остаётся верхний участок у пика. **Не «нигде»** ✗ |
| **(B)** с привязкой к минимуму | `T = min + p · (max − min)` | `T = min` → весь график ✓ | `T = max` → нигде ✓ |

**(A) опровергается собственным требованием «100% — ни для чего».** Значит,
формула **(B)**, а p — это доля пути от минимума к максимуму, а не доля от
размаха.

Итоговая формула:

```
mMin = min_t |beat_base(t)|
mMax = max_t |beat_base(t)|
T(p) = mMin + (p / 100) · (mMax − mMin)
применять(period) ⟺ |beat_base(t)| ≥ T(p)
```

**Проверка на «Циркадном ритме».** Узлы beat: 3, 6, 8, 20, 25, 18, 12, 10 Гц.
При MONOTONE-интерполяции `|beat| ∈ [3; 25]`, то есть `T(p) = 3 + 22p`:

| p | Порог | Территория | Покрытие |
|---|---|---|---|
| 0% | 3.0 Гц | 00:00–24:00 | 100% |
| 50% | 14.0 Гц | ≈07:30–17:00 | ≈40% |
| 100% | 25.0 Гц | — | 0% |

p=50% даёт ровно то, что интуитивно нужно: впадины ложатся на рабочий день
(бета/гамма), а ночь (дельта/тета, где расслабляться уже некуда) остаётся
нетронутой.

## 2. Пять жёстких правил

### R1. Порог считается ТОЛЬКО по базовой кривой

`beat_base(t)` — кривая **до** наложения расслабления. Не по
`curveWithRelaxation`, не по предыдущему кадру.

Иначе возникает петля: расслабление снижает beat → максимум падает → порог
падает → территория расширяется → снижается ещё сильнее. Результат
недетерминирован и зависит от порядка пересчёта. Порог — функция только от
исходных точек пресета и p.

### R2. Мера — модуль `|beat|`, а не знаковый beat

Проект использует знаковую семантику `beat = right − left`: знак задаёт
раскладку каналов, слышимая пульсация — это `|beat|`. Расслабление имеет смысл
там, где пульсация **быстрая** (высокий уровень возбуждения), независимо от
того, какое ухо слышит более высокий тон.

Для пресета −20…+20 Гц знаковая формула дала бы `T = 0` на p=50%, то есть
«расслабляться только там, где правый канал выше левого» — бессмысленное
правило. Модуль даёт «расслабляться на пиках обеих полярностей».

Для всех пресетов с положительным beat (подавляющее большинство) `|beat| ≡ beat`,
то есть правило ничего не меняет относительно интуитивного ожидания.

### R3. Экстремумы — по сэмплам кривой, а не по узлам

`mMin`/`mMax` берутся из выборки интерполированной кривой (N сэмплов за сутки),
а не из `points.map { it.beatFrequency }`.

Причина: при `CARDINAL` сплайн даёт overshoot — реальная кривая выходит за
пределы узлов. Если считать порог по узлам, то:
- на p=100% над порогом окажутся участки, где сплайн вылетел выше `max` →
  «ни для чего» не выполняется;
- границы территории разъедутся с нарисованной кривой.

Рекомендуемое `N = 720` (шаг 2 мин). Ниже — про стоимость.

### R4. p=0 и p=100 — отдельные выходы, а не пределы формулы

```
p <= 0   → территория = все сутки (early return, без сэмплирования)
p >= 100 → пустой список впадин (early return)
```

Формула и так даёт правильный результат, но с оговоркой на строгое/нестрогое
сравнение: на p=0 порог равен `mMin`, и условие `|beat| > T` исключило бы ровно
одну точку минимума; на p=100 при `≥` включился бы ровно пик. Явные выходы
превращают «почти везде / почти нигде» в гарантию, и заодно экономят
сэмплирование на p=0 (самый частый случай — дефолт).

### R5. Вырожденный диапазон (`mMax − mMin < eps`)

Плоская кривая биений (в том числе новая кривая из одной точки). Размах ноль,
«верхнюю половину» выделить нечем. Правило: **p < 100 → применяем везде**
(порог формально достигнут всюду), p = 100 → нигде. Так функция остаётся
видимой и не выключается молча. Задокументировать в KDoc.

## 3. Архитектура: генератор должен перейти от ПОДМЕНЫ к СЛИЯНИЮ

Это главное последствие фичи, и оно не очевидно из постановки.

**Как сейчас.** `RelaxationModeSettings.generateVirtualPoints` возвращает только
виртуальные точки, а `BinauralPreset.curveWithRelaxation` и
`NativeAudioEngine.updateConfig` строят кривую **исключительно по ним** —
реальные точки отбрасываются. Это корректно, пока впадины покрывают сутки
равномерной сеткой: между впадинами кривая всё равно где-то рядом с базовой.

**Почему ломается.** Ограничитель требует, чтобы вне территории кривая была
**точно** базовой — это и есть смысл «не применять». Если по-прежнему
использовать только виртуальные точки, то между двумя впадинами кривая
интерполируется между точками t4 и t1, лежащими на базовой кривой, но **не по
базовой кривой**: её собственные узлы в этом промежутке потеряны.

**Решение — слияние.** Итоговый набор точек:

1. Узлы базовой кривой, которые **не попадают внутрь** ни одной впадины
   (время `t` вне `[start; start + fullPeriod)` для всех впадин).
2. Точки самой впадины `t1…t4`.
3. Всё это складывается в существующий `LinkedHashMap<Int, FrequencyPoint>`
   с правилом «поздняя запись побеждает»: совпадения времён (например, узел
   базовой кривой ровно на краю впадины) разрешатся автоматически.

Побочный эффект — **исправление текущей неточности**: сегодня между впадинами
сплошная кривая отклоняется от базовой (пунктирной) линии, которую рисует
`showDashedBase`. После слияния вне впадин они совпадут.

> **Важно:** это меняет звук существующих пресетов на p=0 — кривая между
> впадинами станет точнее следовать базовой. Отклонение сегодня невелико
> (сплайн сглаживает), но перед выкаткой стоит сверить график «расслабление
> вкл/выкл» визуально. Альтернатива — сохранить старую подмену при p == 0 —
> создаёт разрыв непрерывности при p = 0 → 1% (внезапно появляются узлы
> базовой кривой, кривая между впадинами прыгает). Рекомендуется слияние
> всегда.

**Оговорка про интерполяцию.** Узел базовой кривой, оказавшийся рядом с краем
впадины, не удаляется, а край впадины добавляется как новая точка. Сплайн через
`{A, t1, B}` не тождествен сплайну через `{A, B}`, даже если `t1` лежит ровно на
исходной кривой. При `LINEAR` разницы нет (точки коллинеарны), при `MONOTONE`
она пренебрежимо мала, при `CARDINAL` — заметна на глаз. Это цена точечного
представления кривой, она уже заложена в архитектуру.

## 4. Размещение впадин внутри территории

### 4.1 Сетка: отступ от начала отрезка

Первый период **не** начинается в `a`. Перед ним выдерживается тот же самый
интервал, что и между периодами — `gapBetweenRelaxationMinutes`. Это прямой
отказ от прежней схемы «впадина вплотную к левому краю»: граница `a` — это не
начало чего-то, а всего лишь точка пересечения `|beat|` с порогом. Пользователь
только **входит** в зону высоких биений, и разгрузка там ещё не нужна.

```
fullPeriod = 2·transition + duration
step       = fullPeriod + gap
start_k    = a + gap + k·step,  k = 0, 1, 2, …
D          = L − gap               // доступно под сетку после вступительной паузы
n          = ceil(D / step)        // если D > 0; иначе 0
```

Структура отрезка: `[пауза][впадина][пауза]…[впадина][хвост]`.

**Откуда берётся отступ.** Он не вводит нового параметра: «заданный интервал от
начала» — это `gapBetweenRelaxationMinutes`, уже лежащий в предустановке.
Отсюда же следует правило: **пауза перед первым периодом ровно такая же, как
между периодами**. Сетка получается строго равномерной, ни один интервал не
подгоняется под длину отрезка.

Если `gap = 0`, отступа нет вовсе: `start_0 = a`. Это не противоречие, а
вырождение — интервала, который надо выдержать, просто не задано.

**Равномерность через полночь.** Раньше сетка начиналась в 00:00, и на стыке
суток зазор получался обрубком: последняя впадина дня заканчивалась в 23:27, а
первая впадина следующего дня начиналась в 00:00 — то есть 33 минуты вместо 45.
С отступом и с усечением последнего периода (§4.2) сутки заполняются ровно:
21 полный период + 1 усечённый (9 мин) + 22 паузы по 45 мин = 27 000 + 59 400
= 86 400. Значит, пауза между последним периодом дня N и первым периодом дня
N+1 равна ровно `gap`: расписание становится строго периодическим, без «шва» в
полночь.

**Проверка на примере.** Территория 07:30–17:00 = 34 200 с, дефолты
(`fullPeriod = 1260 с`, `step = 3960 с`, `gap = 2700 с`): `D = 31 500`,
`n = ceil(31 500 / 3960) = 8` периодов; первый начинается в 08:15 — через 45
минут после входа в территорию, а не в 07:30.

### 4.2 Последний период: усечение

```
available = D − (n−1)·step          ∈ (0; step]
```

Усекается только последний период (`k = n−1`), и только в сторону уменьшения.
Все предыдущие всегда полные. Три ветви:

| Условие | Исход |
|---|---|
| `available ≥ fullPeriod` | период полный; дальше простаивает хвост `available − fullPeriod` (≤ `gap`) |
| `2·transition ≤ available < fullPeriod` | усечённый **по плато**: `duration' = available − 2·transition`; переходы целы, глубина полная |
| `0 < available < 2·transition` | усечённый **по переходам**: `duration' = 0`, `transition' = available/2`, глубина умножается на `k = transition'/transition` |

Нижнего порога у `available` нет: при `available → 0` коэффициент `k → 0`,
период плавно вырождается в микроскопический треугольник ничтожной глубины, а
не исчезает скачком. Период не ставится вообще только при `D ≤ 0` (§4.3).

**Конец периода обязан совпасть с концом отрезка.** В любом непустом исходе
`t4` лежит ровно в `a+L` и равен **базовому** значению кривой, поэтому:

- период ни на секунду не выходит за правую границу — сниженные частоты не
  попадают туда, где `|beat| < T`;
- на границе нет ни разрыва, ни ступеньки: за `t4` идёт базовая кривая, и
  значения совпадают.

Именно поэтому усечение допустимо, а «выпустить период за край» — нет: при
обрезке посреди рампы `t4` лежал бы на сниженном уровне, и на границе
получились бы вертикальный обрыв на графике и резкий подъём частоты на слух.
Подробнее — §4.4.

**Глубина падает пропорционально переходам: сохраняется скорость хода.** В
третьей ветви плато уже обнулилось, а в оставшееся место не влезают и два
полных перехода. Сжимаем их: `transition' = available / 2`. Но если оставить
глубину прежней, период станет столь же глубоким, зато вдвое более крутым —
короткий резкий провал частоты, выбивающийся из ритма всех остальных периодов.
Поэтому глубина снижения масштабируется тем же коэффициентом:

```
k                  = transition' / transition = available / (2·transition)   ∈ (0; 1)
beatReduction'     = beatReduction    · k
carrierReduction'  = carrierReduction · k
```

При этом **скорость изменения частоты остаётся той же, что и у обычного
периода**:

```
скорость = глубина / переход = (k · глубина) / (k · переход) = const
```

То есть усечённый период — это не «испорченный» период, а геометрически
подобный, просто меньший: тот же угол хода, та же форма, меньше длина и
меньше глубина. Ровно это и нужно, чтобы он не выделялся на слух.

Ветви 2 и 3 непрерывны на стыке: при `available = 2·transition` вторая даёт
`duration' = 0` и `k = 1`, третья — `transition' = transition` и `k = 1`.
Результат один и тот же, отдельного случая нет.

**Случай «период закончился ровно на границе»** (`available = fullPeriod`)
безопасен по той же причине: `t4` — базовое значение. Отдельной обработки не
требует.

Числа для дефолтов (`transition = 3 мин = 180 с`, `duration = 15 мин`,
`gap = 45 мин` → `fullPeriod = 1260 с` = 21 мин, `step = 3960 с` = 66 мин,
`2·transition = 360 с` = 6 мин):

| Территория | `L` | `D = L − gap` | `n` | `available` | Ветвь | Исход |
|---|---|---|---|---|---|---|
| p=0, сутки | 86 400 | 83 700 | 22 | 540 с = 9 мин | 2 | плато **3 мин** вместо 15; рампы по 3 мин целы, глубина полная |
| p=50%, 07:30–17:00 | 34 200 | 31 500 | 8 | 3780 с = 63 мин | 1 | полный период + хвост 42 мин |
| 2 ч 13 мин | 8 000 | 5 300 | 2 | 1340 с | 1 | полный период + хвост 80 с |
| 51 мин | 3 060 | 360 | 1 | 360 с | 2 | треугольный период: плато 0, рампы по 3 мин, глубина полная |
| 50 мин | 3 000 | 300 | 1 | 300 с | 3 | рампы по **150 с**, плато 0, `k = 0.83` → глубина 83% |
| 46 мин | 2 760 | 60 | 1 | 60 с | 3 | рампы по **30 с**, плато 0, `k = 0.17` → глубина 17% |
| 45 мин 1 с | 2 701 | 1 | 1 | 1 с | 3 | рампы по **0.5 с**, плато 0, `k = 0.003` → глубина 0.3%: период практически неотличим от базовой кривой |

**Совпадение точек по целым секундам.** При `available` в единицы секунд
времена `t1`…`t4` после округления до целых секунд могут совпасть. Правило:
внутренние точки (`t2`/`t3`) при совпадении **не издаются** — приоритет у `t1`
и `t4`, потому что их значения базовые и конфликт разрешается в пользу базовой
кривой. Глубина в этот момент уже ничтожна, потеря неотличима от отсутствия
периода.

**Следствие для p=0 (важно).** При p=0 территория — все сутки, и общий
алгоритм даёт **22 периода, из которых первый начинается в 00:45, а последний
усечён до 9 минут**. Это уже не сегодняшние «22 впадины, начиная с 00:00»:
расписание существующих пресетов изменится. Платим мы за равномерность
интервалов, включая стык суток (§4.1). Особый случай для p=0 — в §7.4.

### 4.3 Когда период не ставится вовсе

Единственная ситуация — **`D ≤ 0`, то есть `L ≤ gap`**: отрезок не длиннее
вступительной паузы, ни одного периода быть не может. Пустой список.

Территория при этом остаётся на базовой кривой. Это не ошибка и не требует
отдельной обработки: генератор вернёт меньше точек, слияние (§3) даст чистую
базовую кривую.

Отдельного минимального порога для усечённого периода **нет** и не нужно:
пропорциональное снижение глубины (§4.2) само гасит все проблемы микроскопических
остатков. Чем короче остаток, тем меньше глубина — при `available` в единицы
секунд снижение уходит в доли процента, то есть период исчезает **плавно**, а
не отбрасыванием. Совпадение точек по целым секундам при этом не портит ни
звук, ни сплайн (§4.2).

### 4.4 Отвергнутые варианты

Все они меняют интервалы, заданные в предустановке, поэтому закрыты.

**Растяжение зазоров под длину отрезка** (`gap' = (L − n·fullPeriod)/(n − 1)`,
периоды от края до края). Хвоста нет, края симметричны, но `gap` перестаёт
равняться заданному: на p=0 получилось бы 46.6 мин вместо 45.

**Добивка хвоста периодом вплотную к правому краю.** Даёт последний зазор,
отличный от остальных, а в предельном случае — два склеенных периода подряд.

**Пропорциональное сжатие периода под короткий отрезок**
(`scale = L/fullPeriod`, жмутся и переход, и плато). Было в первой версии
документа, снято: это «вольное изменение интервалов» сверх разрешённого.
Сжатие переходов допустимо **только** в ветви 3 §4.2 — когда плато уже
обнулилось, период всё равно не влезает, и глубина снижается тем же
коэффициентом. Сжимать переход, оставляя глубину полной, нельзя: получился бы
короткий резкий провал с **другой** скоростью хода частоты — он выбивался бы из
ритма остальных периодов.

**Период через край.** Выпустить последний период за `a+L` и дописать его до
конца. Отвергнуто по двум причинам, и разрешение на усечение ни одной из них
не снимает:

1. Сниженные частоты попадают на участок, где `|beat| < T` — туда, куда
   пользователь просил их **не** ставить. Усечение этого не делает: период
   остаётся внутри отрезка.
2. При обрезке посреди рампы `t4` лежит на сниженном уровне → вертикальный
   обрыв на графике, резкий подъём частоты в звуке. Усечение плато этой проблемы
   лишено: рампы целы, `t4` = базовое значение.

**Глобальная сетка от 00:00** (ставить только те периоды, что целиком попали в
территорию). Давала бы приятное свойство — периоды вообще не двигаются при
движении слайдера. Но она несовместима с требованием отступа от начала
отрезка: при глобальной сетке первый период начинается где угодно относительно
`a`, в том числе вплотную к нему, а короткие пики не получают ни одного периода.
### 4.5 Морфология маски: закрытие дыр и удаление крошек

Две операции над бинарной маской, обе — по кругу:

1. **Closing: закрыть дырки короче `MIN_HOLE`.** Без этого возникает
   специфический артефакт: если `|beat|` ненадолго (на 2–3 минуты) проваливается
   под порог, территория разрывается на две, каждая получает собственную сетку
   от своего левого края, и в середине того, что слушателю слышится как одна
   длинная зона расслабления, появляется короткий **возврат к базовому уровню**.
   Рекомендуемое `MIN_HOLE = max(gap, 5 мин)` — дырка короче паузы между
   впадинами не должна разрывать отрезок.
2. **Despeckle: выбросить участки короче `MIN_RUN`.** Убирает «крошки» из
   отдельных сэмплов у порога и дрожание границ при движении слайдера.
   Рекомендуемое `MIN_RUN = 2·шаг сэмплирования` (при N=720 это 4 мин) — но не
   меньше, чем хватает для осмысленной впадины.

Порядок важен: сначала closing, потом despeckle. В обратном порядке короткий
участок, примыкающий к дырке, удалился бы до того, как дырка сомкнёт его с
соседом.

### 4.6 Склейка через полночь

Сутки — окружность. Алгоритм:

1. Если все сэмплы `true` — один интервал `[0; 86 400)`. **Без этого guard'а
   склейка «первый и последний участок» дала бы интервал длиной 172 800.**
2. Иначе повернуть маску так, чтобы она начиналась с `false`, и собрать
   линейные серии `true`. Поворот снимает весь специальный код для
   «участка через границу суток».
3. Границы участка уточнить: линейная интерполяция между соседними сэмплами,
   между которыми произошёл переход через порог, плюс 2–3 шага бисекции —
   локальный экстремум у порога иначе сдвинет границу.
4. Раскладку вести в «развёрнутых» координатах `[a; a+L)` (время может
   превышать 86 400), затем времена точек брать по модулю 86 400.
5. Проверка «узел базовой кривой внутри впадины» обязана проверять и `t`, и
   `t + 86 400` — иначе узел в 00:30 не распознается как лежащий внутри
   впадины, начавшейся в 23:50.

## 5. Стоимость

`generateVirtualPoints` вызывается из `NativeAudioEngine.updateConfig`, который
работает в `prepare()` на writer-потоке (`BinauralWriter-N`, приоритет AUDIO),
а не в жёстком аудио-колбэке. Тем не менее бюджет не безразмерный.

| | Интерполяций кривой |
|---|---|
| Сейчас (дефолты) | 22 впадины × 4 точки × 2 кривые = **176** + `CardinalTension.forPoints` на ~88 точках |
| + маска при N=1440 | +1440 → ~9× |
| + маска при N=720 | +720 → ~5× |
| + маска при N=288 | +288 → ~2.6× |

Одна интерполяция — `O(log n)` бинарный поиск плюс константа, то есть единицы
микросекунд. Даже 1440 сэмплов — это доли миллисекунды, и происходит только при
смене настроек (UI коммитит слайдер на `onValueChangeFinished`, а не на каждый
пиксель).

**Рекомендация: N = 720** (шаг 2 мин) — погрешность границы ≤ 2 мин, стоимость
незначима. Границу территории дополнительно уточнять линейной интерполяцией
между двумя соседними сэмплами, между которыми произошёл переход через порог:
тогда точность позиции края — секунды, и можно смело снизить N до 288, если
профилирование покажет необходимость.

Кэшировать маску **не** рекомендуется: `RelaxationModeSettings` — data class,
участвующий в равенстве `PlaybackSpec`; любое кэш-поле в теле потребует
`@Transient` и аккуратного отношения к потокам, а выигрыш нулевой.

### Модель — `core/audio/.../model/BinauralPreset.kt`

```kotlin

 * Ограничитель применения периодов расслабления: 0-100%.
 *
 * 0%   — периоды накладываются на весь график;
 * 100% — периоды не накладываются ни на что;

 * биений: знак beat задаёт раскладку каналов, а не уровень возбуждения.
 */
val beatGatePercent: Int = 0     // 0-100%
```

- константа `MAX_BEAT_GATE_PERCENT = 100` в companion (рядом с
  `MAX_CARRIER_REDUCTION_PERCENT`);
- `require(beatGatePercent in 0..MAX_BEAT_GATE_PERCENT)` в `init`;
- дефолт **0** — существующие пресеты обязаны звучать как раньше;

- **убрать из цикла guard'ы `if (t < daySeconds)`.** Время точки нормализовать
  по модулю 86 400 **до** проверки. С усечением последнего периода точка
  `t4` регулярно попадает ровно в 86 400, и старый guard её отбрасывает —
  период остаётся незакрытым (строка 20 таблицы §4.7);
- константы генератора:

```kotlin
private const val GATE_SAMPLE_COUNT = 720          // шаг сэмплирования 2 мин
private const val GATE_MIN_RUN_SECONDS = 240L      // despeckle: участок короче — выбросить
private const val GATE_MIN_HOLE_SECONDS = 2700L    // closing: дырку короче — сомкнуть
                                                   // (по умолчанию = max(gap, 5 мин),

```

Усечённый период (ветвь 3) получает **свои** коэффициенты снижения, а не
поля настроек напрямую. Практически это значит, что `reduceFrequencies` должна
принимать глубину параметром, а не читать `beatReductionPercent` /
`carrierReductionPercent` внутри себя.

`GATE_MIN_HOLE` логически зависит от `gapBetweenRelaxationMinutes`, поэтому
вычислять его из настроек, а не брать константой: дырка короче паузы между
впадинами не должна разрывать отрезок.

### Тесты

1. **Golden (p=0):** на дефолтных параметрах 22 периода; `start_k = 2700 +
   k·3960` (первый в 00:45, **не** в 00:00); последний (`k = 21`, старт 23:51)
   усечён — плато 180 с вместо 900, `t4 = 86 400` → время 0.
2. `p = 100` → пустой список → движок откатывается на базовую кривую.
3. Покрытие монотонно не возрастает по p (проверить на 0, 25, 50, 75, 100).
4. Плоская кривая биений: p<100 → применяется везде.
5. Территория через полночь: все времена точек в `[0; 86400)`, дублей по
   времени нет.
6. Вне периодов кривая совпадает с базовой (сэмплы, `LINEAR` и `MONOTONE`).
7. Знак beat сохраняется при снижении до 100% внутри периодов (старое правило).
8. Вырождение `transition = duration = 0` → пусто (как сейчас).

Дополнительно — на краевые случаи §4.7. Тесты 9–14 параметрические (перебор
`transition` × `duration` × `gap` × `p`), а не по одному примеру: именно здесь
легко «подогнать» интервал и не заметить.

9. **Инвариант «интервалы ровно из предустановки»:**
   - `start_0 − a == gap` — отступ ровно заданный, ни больше ни меньше;
   - `start_{k+1} − start_k == step` для всех k;
   - `transition` у всех периодов один и тот же, **кроме последнего**, и у
     последнего он равен либо `transition`, либо `available/2` (ветвь 3 §4.2);
   - `duration` у всех периодов один и тот же, **кроме последнего**.
10. **Инвариант «период не выходит за границы»:** ни один период не начинается
    раньше `a` и не заканчивается позже `a+L`; `t1` и `t4` у **каждого**
    периода равны базовому значению кривой (автоматически следует из целых
    рамп). Это и есть защита от «впадины через край».
11. **Усечение по плато:** при `2·transition ≤ available < fullPeriod`
    последний период имеет `duration' = available − 2·transition`, оба рампа
    полные, глубина полная, `t4` = база и лежит ровно в `a+L`.
12. **Равномерность через полночь:** при p=0 разность между `t4` последнего
    периода суток (время 0) и `t1` первого периода суток равна ровно `gap`.
    Защита от «шва» в полночь (§4.1).
13. `L ≤ gap` → ноль периодов, кривая = базовая (строка 10 таблицы §4.7).
14. **Усечение по переходам:** при `0 < available < 2·transition`
    последний период имеет `transition' = available/2`, плато 0, а
    `beatReduction` и `carrierReduction` умножены на
    `k = available/(2·transition)`. Отдельно — **инвариант скорости хода**:
    отношение `(глубина снижения) / transition'` у усечённого периода совпадает
    с тем же отношением у полного (§4.2).
15. **Непрерывность на стыке ветвей:** при `available = 2·transition ± 1 с`
    результаты ветвей 2 и 3 различаются не больше чем на `eps` — скачка при
    переходе от усечения по плато к усечению по переходам нет.
16. **Микроскопический `available`** (единицы секунд): период не отбрасывается,
    а вырождается — глубина < 1%, `t4` = база и лежит ровно в `a+L`; совпавшие
    по целым секундам внутренние точки не издаются (§4.2).
17. `transition = 0` → ветвь 3 недостижима, деления на `2·transition` не
    происходит; период усекается только по плато, глубина полная.
18. Дырка короче `MIN_HOLE` → участки слились; **нет возврата к базовому
    уровню внутри зоны** (регрессионный тест на артефакт §4.5).
19. `t4 = 86 400` → точка с временем 0, значение базовое, дублей по времени
    нет. Тест обязан ловить именно отбрасывание точки guard'ом
    `t < daySeconds` (строка 20 таблицы §4.7).
20. Вся маска `true` → ровно 86 400 с территории, не 172 800.
21. `|beat| = T` на плато при типе `STEP` → плато входит целиком, граница не
    «мигает» между соседними сэмплами.

## 7. Открытые вопросы

### 7.1 Порог по частоте или по квантили покрытия?

Альтернатива формуле (B): слайдер задаёт **долю суток с максимальным `|beat|`**
— «50%» означает «применить к половине суток, где биения быстрее всего».

- **Плюсы:** покрытие монотонно и предсказуемо по определению; нет проблемы
  плоской кривой; нет «мертвых» значений, когда весь график выше порога.
- **Минусы:** порог в Гц становится непредсказуемым для пользователя; при
  небольшой правке кривой территория может заметно переехать; не совпадает с
  поставленной задачей.

Рекомендуется **порог по частоте** (как просили), а квантильный вариант
отложить: если после практики окажется, что пользователь подбирает процент
«на глаз» по покрытию, перейти на него легко — меняется только
`qualifyingWindows`.

### 7.2 Жёсткий порог или мягкий край?

Жёсткое `|beat| ≥ T` означает, что при движении слайдера впадины
**появляются и исчезают целиком**. Звук при этом не щёлкает (смена кривой идёт
через zero-overlap handoff), а коммит происходит на отпускании слайдера, так
что это терпимо.

Если захотите плавности: ввести узкую полосу гистерезиса `±h` (2–4% размаха) и
внутри неё масштабировать **глубину** впадины (`carrierReduction`/`beatReduction`
умножаются на `smoothstep`). Тогда впадины на краю территории не выключаются, а
плавно мельчают. Цена — «не применять» перестаёт быть буквальным.

### 7.3 Отступ перед первым периодом: брать `gap` или завести отдельное поле?

В §4.1 отступ принят равным `gapBetweenRelaxationMinutes` — интервалу, который
уже лежит в предустановке. Плюсы: нового поля нет (ни в модели, ни в
сериализации, ни в UI), сетка строго равномерна, и фраза «все интервалы заданы
в предустановке» выполняется буквально.

Минус: отступ перед первым периодом теперь всегда равен паузе между периодами.
Если понадобится «входить в зону быстро, а между периодами выдерживать долгую
паузу», потребуется отдельное поле (`offsetBeforeFirstRelaxationMinutes`,
дефолт = `gap`). Алгоритм при этом не меняется: в формуле §4.1 `gap`
заменяется на `offset`, а `step` остаётся `fullPeriod + gap`.

Пока отдельного поля не заводим — сценария, где они должны различаться, не
видно.

### 7.4 p=0: общий алгоритм или особый случай?

Самый крупный поведенческий выбор, оставшийся в документе.

Общий алгоритм (принят в §4.1–4.2) на p=0 даёт 22 периода, первый из которых
начинается в 00:45, а последний усечён до 9 минут. Сегодня на p=0 — 22 впадины,
первая из которых начинается в 00:00. То есть **расписание существующих
пресетов изменится**.

За общий путь:

- один код, нет ветки «а вдруг территория — это все сутки»;
- интервалы строго равномерны, включая стык суток: пауза между последним
  периодом дня N и первым периодом дня N+1 равна ровно `gap`. **Сегодня она
  равна 33 минутам вместо 45** (§4.1), то есть текущее расписание на самом деле
  непериодично, и «совместимость» с ним — ценность спорная;
- p=0 становится пределом p→0+, а не отдельным режимом: при движении слайдера
  от 0 к 1% сетка не перескакивает.

За особый случай (p=0 → сетка от 00:00, как сейчас):

- существующие пресеты не меняют звучания;
- но появляется скачок при переходе 0% → 1% (вся сетка сдвигается на `gap`),
  и «шов» в полночь остаётся.

Если выбирается особый случай, оформлять его надо как early-out рядом с R4
(§2), а не как `if` внутри раскладки — иначе формулы §4.1 перестают быть
проверяемыми.

### 7.5 Сетка едет вместе с порогом — терпимо ли?

Граница `a` — это точка пересечения `|beat|` с порогом, поэтому при изменении p
она движется, а вместе с ней движется **вся** сетка целиком (§4.1). Коммит
происходит на отпускании слайдера, смена кривой идёт через zero-overlap
handoff, так что щелчка нет; но между соседними значениями p расписание может
заметно переехать.

Округление `a` вниз до 15 минут, предлагавшееся раньше, **снято**: оно
удлиняет первую паузу по сравнению с `gap`, то есть нарушает требование
жёстких интервалов.

Если езда покажется назойливой, остаются два варианта — и оба требуют отказа
от одного из принятых правил:

- привязать сетку к пику `|beat|` внутри отрезка (или к центроиду превышения
  `|beat| − T`): периоды у пика стоят на месте, меняется только их число у
  краёв. Но это ломает отсчёт «от начала отрезка» (§4.1).
- глобальная сетка от 00:00 (§4.4): не двигается вовсе, но первый период
  начинается где попало относительно `a`.

По умолчанию — не делать ничего.

### 7.6 Нужен ли такой же ограничитель по несущей?

Сейчас порог только по `|beat|`. Это оправдано: именно частота биений
соответствует ритму ЭЭГ (дельта…гамма), то есть уровню возбуждения, а несущая
— это в первую очередь тембр. Ограничитель по несущей добавлять не предлагается,
пока не появится сценарий.
